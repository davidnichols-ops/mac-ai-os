# MAOS Architecture — Adaptive Operator Runtime Substrate

## Mission

MAOS is not an AI-assisted application. It is a **local AI operating environment** —
the execution substrate that any sufficiently capable model can inhabit.

The current Qwen3.5-9B Adaptive Operator v2 is a capable prototype. The architecture
is NOT optimized around its limitations. It is built for the future v3/v4 models that
will be trained on trajectories generated by this system.

**MAOS is the product. The model is the replaceable intelligence layer.**

## Design Principles

1. **Model is the brain, runtime is the body** — no hardcoded intelligence in Python
2. **Everything observable** — every step is training-quality telemetry
3. **Capabilities, not agents** — the model orchestrates; tools execute
4. **Model-replaceable** — build for v3/v4, not current model limitations

## Core Module: `app/core/`

The execution substrate lives in `app/core/`:

| File | Purpose |
|------|---------|
| `agent_loop.py` | The think-act-observe-verify cycle |
| `tool_executor.py` | Tool execution with safety gates |
| `safety.py` | Risk classification (LOW/MEDIUM/HIGH/CRITICAL) |
| `trajectory.py` | Training-quality telemetry recording |
| `state.py` | Mutable execution state |
| `system_prompt.py` | Dynamic system prompt assembly |

## Two Modes

- `maos chat` — pure conversation, no tools (the model just talks)
- `maos do "..."` — full agent loop with all tools available

## Tool Calling

The v2 model doesn't support native function calling. Tool definitions are injected
into the system prompt as formatted text. The model emits tool calls in a structured
format that the provider parses:

```

```

The parser supports 5 formats for robustness:
1. <tool_call> JSON blocks (primary)
2. Qwen3.5 XML-style (`<function=name>`)
3. Pipe-delimited (`|tool_call|`)
4. JSON code blocks
5. Bare JSON

## Safety

Every tool call passes through the SafetyGate:
- **LOW**: read-only (auto-approved)
- **MEDIUM**: side-effects, reversible (auto-approved)
- **HIGH**: potentially destructive (requires user approval)
- **CRITICAL**: irreversible (always blocked unless explicitly approved)

## Training Data Generation

Every `maos do` execution produces a trajectory JSON file in `data/trajectories/`.
This is the atomic unit of training data for future Adaptive Operator models.

```json
{
  "trajectory_id": "traj_...",
  "schema_version": "2.0.0",
  "task": "list the files in the current directory",
  "model_name": "...",
  "steps": [...],
  "success": true,
  "total_steps": 4,
  "total_tool_calls": 1,
  "time_to_completion_s": 111.2
}
```

## What Stays As-Is

These subsystems work well and are not changed:
- Database (SQLite), Retrieval (Chroma), Telemetry, Event bus
- Permission system, MCP server, Guards, Workflow engine
- Config system, Hardware detection
- Blackboard, Attention daemon, Learning system

These are connected to the agent loop as context sources (Phase 4).
